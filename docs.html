HLS & M3U8 Documentation

Understand playlist structure, adaptive streaming and common playback constraints

1. What are HLS and M3U8?

HTTP Live Streaming (HLS) is an adaptive streaming protocol. A player downloads a text playlist, then requests media segments over HTTP or HTTPS. M3U8 is the UTF-8 playlist format commonly used to describe those streams.

A playlist is not the video itself. It is a manifest that points to variant playlists, audio tracks, initialization data and media segments.

2. Master playlists and media playlists

A master playlist describes available renditions. Each variant can specify bandwidth, resolution, codecs and a URI for its media playlist. A player can switch between variants as network conditions change.

A media playlist describes the media segments for one rendition. It commonly contains an #EXTINF duration followed by a segment URI for each item.

3. Important HLS tags

  • #EXT-X-STREAM-INF — declares a variant stream and its attributes.
  • #EXTINF — gives the duration and optional title for the next media segment.
  • #EXT-X-TARGETDURATION — declares the maximum segment duration target.
  • #EXT-X-MEDIA-SEQUENCE — identifies the sequence number of the first segment in a playlist.
  • #EXT-X-ENDLIST — indicates that no more media segments will be added.
  • #EXT-X-KEY — describes encryption key information.
  • #EXT-X-MAP — points to an initialization section, often used with fragmented MP4.
  • #EXT-X-DISCONTINUITY — marks a change in the media timeline or encoding parameters.

4. Variants, bandwidth and codecs

Adaptive bitrate streaming publishes multiple renditions of the same content. The player selects a suitable rendition based on available bandwidth, device capability and buffer health. Resolution alone does not determine quality: codec, bitrate, frame rate and encoding settings also matter.

Common media formats include MPEG-TS segments (.ts) and fragmented MP4 segments (.m4s or .mp4). The codecs declared in the playlist must be supported by the browser or playback library.

5. Live streams and video on demand

A live media playlist is updated as new segments become available and usually does not contain #EXT-X-ENDLIST. A video-on-demand playlist is generally complete and may include the end-list tag. A short playlist is not necessarily broken: a live window may intentionally expose only recent segments.

6. CORS and HTTPS

Browsers enforce cross-origin rules. A playlist may load in a desktop player but fail in a browser if the server does not return suitable CORS headers for the manifest, media segments, keys or initialization files. HTTPS pages also cannot freely load insecure HTTP media because of mixed-content restrictions.

When debugging, inspect the browser network panel for the exact request that fails. A 403 can indicate authorization or an expired signed URL; a 404 can indicate a stale segment path; a CORS error means the browser did not allow the requesting page to read the response.
